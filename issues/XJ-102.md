# XJ-102 · 设计令牌扩展：达标语义色、徽章、任务完成态、印章、周报封面

> **归属**：设计系统 Agent（`ds`） · **波次**：W1 · 地基 · **优先级**：P0 · **规模**：S

> **价值**：给后续所有「有状态」的视觉提供统一语义色，避免每个页面各自定义达标绿/警示红。

## 背景

- 现有令牌齐全但缺「状态语义色」：档案页达标条、徽章锁定态、任务完成态、印章红都没有对应变量。
- 项目有三套皮肤（默认柔金、`.elder` 乐龄墨绿、`.night` 臻享夜色金），任何新令牌必须在三套下都有值，否则切肤后会回落成继承值导致不可读。

## 范围与实现要点

1. 新增 `--meter-ok` / `--meter-near` / `--meter-low`（达标 / 略偏 / 警示），用于档案与周报的进度条。
2. 新增 `--badge-bg` / `--badge-lock`（徽章已解锁底 / 未解锁底）。
3. 新增 `--task-done`（任务完成态底）。
4. 新增 `--stamp-ink`（印章红）。
5. 新增 `--report-bg` / `--report-ink`（周报封面，**刻意不随皮肤**，固定夜色黑金，形成「报告 = 珍视」的视觉语言）。
6. 在默认、`.xj.elder`、`.xj.night` 三处同步赋值；夜色金皮肤下需提高亮度补偿。

## 验收标准

- [ ] 三套皮肤下五个新分组变量都有显式值（用样式检查或截图证明，不依赖继承）。
- [ ] 达标条颜色在浅底与深底上都能与背景形成可辨差异（对比度 ≥3:1，文字类 ≥4.5:1）。
- [ ] `--report-*` 在三套皮肤下取同一组值（不随皮肤变化）。
- [ ] 新增变量不影响任何既有页面渲染（改动前后截图对比，仅新增、无覆盖）。

## 禁止事项

- ⛔ 不要修改变量已有名字或值（会引发全站视觉回归）。
- ⛔ 不要把新令牌定义在组件内（组件内只允许消费，不允许定义皮肤级变量）。
