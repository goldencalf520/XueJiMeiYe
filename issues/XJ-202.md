## 背景

- 会员等级为 `TIER_NAMES = { A: 臻享会员, B: 尊享会员, C: 悦享会员 }`，另有访客与乐龄维度。
- 设计文档给出 18 个首页组件 × 5 种状态的启用矩阵，但代码里没有统一的编排层。

## 范围与实现要点

1. 新增 `HomeGate.vue` 或在 `HomeRender.vue` 内实现模块编排层，按用户状态决定模块启用与顺序。
2. 访客：只讲「六个维度是什么 + 免费领体检券」，不展示个人数据与任务。
3. C 悦享：全套工具 + 游戏化任务（签到 / 今日 3 件事 / 存折 / 魔镜）。
4. B 尊享：社交邀约前置（讲座占座 / 结伴拼团）+ 文旅权益 + 升级进度。
5. A 臻享：**弱化积分与任务**，强化专属顾问、权益质感、年度报告入口。
6. 模块编排结果需与设计文档 §4.1 的矩阵逐项对齐。

## 验收标准

- [ ] 访客 / C / B / A 四种状态下首页截图具备明显差异，且与 §4.1 矩阵一致。
- [ ] A 级用户首页不出现积分任务类模块（或明显弱化）。
- [ ] 访客首页不出现任何个人健康数据。
- [ ] 切换用户等级后首页立即重排，无需重启小程序。

## 禁止事项

- ⛔ 不要为四种状态各写一套组件——用编排配置驱动，避免后续维护四份。
- ⛔ 不要修改后端返回结构（后端增强走 XJ-305）。
