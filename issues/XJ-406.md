# XJ-406 · 门店集章册：印章收集形态（不做地图打点）

> **归属**：前端页面 Agent（`fe`） · **波次**：W4 · 互动玩法 · **优先级**：P2 · **规模**：M
> **状态**：`done` · **认领人**：`win-B`
> **价值**：把「去过几家店」变成看得见的印章册。乐龄用户对印章的认知成本远低于地图，同时规避地图数据合规风险。

## 背景

- 设计决策：**不采用地图打点**，改为集章册形态。理由：乐龄用户对印章认知成本低；门店数量少（试点 1 家）地图信息密度不足；规避地图数据合规风险。
- 当前仅五月花店 1 家试点，但数据结构按 N 家设计（D7）。

## 范围与实现要点

1. 顶部进度：金色渐变；「我的健康印章册」+「已集 3 / 6 家」+ 集满奖励说明。
2. 常去门店卡：大缩略图 + 门店名 + 距离 + 标签（已预约 N 次 / 常去）+ **红色圆形印章**（旋转 -12°，含「已盖章 + 日期」），印章用纯 CSS 合成。
3. 待集门店列表：每行「图标 + 门店名 + 距离 + 虚线圆形待盖章」。
4. 盖章规则：① 到店完成项目或体检 ② 出示集章册由顾问扫码 ③ 一月内每店限 1 枚。
5. 主按钮「去门店预约」+ 最近门店距离。

## 验收标准

- [ ] 已盖章 / 待盖章两种印章视觉区分明显，印章有旋转与做旧质感。
- [ ] 印章为纯 CSS 合成，无图片资源。
- [ ] 门店数量为 1 时页面不塌陷（布局兼容 N=1）。
- [ ] 盖章规则文案与后端校验逻辑一致（一店一月一枚）。
- [ ] 页面无任何地图组件、地图 SDK 或地理坐标数据。

## 禁止事项

- ⛔ **不得引入地图 SDK、地图组件或自绘地理数据**。若未来确需真实地图，必须使用腾讯位置服务 SDK / 腾讯地图小程序插件，坐标从其合规接口获取。
- ⛔ 不要用图片做印章（必须纯 CSS 合成以支持三皮肤与乐龄）。
