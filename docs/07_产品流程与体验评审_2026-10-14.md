## 一、产品现状梳理：核心用户旅程地图

### 1.1 四条主旅程的路径还原与顺畅度

**旅程 A：新客转化（登录 → 测评 → 领券）**

```
登录页(卖点卡+手机号) → 基础资料(称呼/出生年份/性别, 可跳过) → 首页
→ 测评介绍(方式三选一) → 关卡地图(7关) → 答题页(逐题保存) → [L3命中 → 紧急页]
→ 完成全部关卡 → 生成结果(三件事/指数/雷达图/就医建议/体检券/初步方案)
```

**顺畅度 ★★★★☆**：逐题保存 + 关卡地图可续答 + "约 8 分钟可分几次完成"的预期管理，是同类测评流程里的优等设计；紧急中断页做得克制且安心（120 大按钮 + "已答的题目都保存好了"）。

**旅程 B：体检闭环（券 → 预约 → 回传 → 方案）**

```
结果页/我的 → 体检券列表 → [状态: issued] 到店出示核销 → [状态: claimed] 预约日期
→ 选号源(14天日历) → C3/C4 开关(默认不勾) → 提交 → 等医院确认 → 医院回传 → 方案更新通知
```

**顺畅度 ★★★☆☆**：券面承诺文案、号源余量提醒（余≤2 黄字）体验细致；但存在两处硬断点（见 2.4-B1/B2）。

**旅程 C：门店转化（方案/首页 → 门店项目 → 意向提交）**

```
方案页"查看门店全部项目与价格" / 我的-门店项目 → 门店页(美团式团购列表)
→ 点项目(带入项目名) → 意向表单 → 提交 → "顾问会在 24 小时内联系您" → （无跟踪入口）
```

**顺畅度 ★★★☆☆**：从种草到提交路径短（2 步）、预填项目名减少输入；提交后是体验黑洞（见 2.4-C1）。

**旅程 D：日常留存（首页 → 魔镜/打卡/游戏/档案）**

```
首页(配置驱动6套布局) → 魔镜(陪聊/读报告/风险安全卡) | 每日打卡/问答/翻牌 | 档案(指数趋势/三色来源标签)
```

**顺畅度 ★★★★☆**：档案页信息架构清晰（指数卡+指标网格+最近记录），三色来源标签帮用户理解"数据从哪来"；方案与打卡未联动是缺憾（见 2.3-D1）。

### 1.2 体验设计亮点（旅程层面确认的优势）

1. **断点续答做到极致**：答题每题 PUT 保存（`question.vue:62`）、介绍页有"上次的测评还没做完，点这里继续"恢复卡（`intro.vue:41`）、关卡地图有全局进度与"还需约 N 分钟"。
2. **预期管理贯穿**：测评前"约 8 分钟"、关卡地图"还需约 X 分钟"、每关"+10 积分已到账"，把最劝退的长流程拆成可感知的小目标。
3. **L3 紧急中断的体验设计**：不等测评结束立即跳转、120 按钮高度 64px、返回路径保留、答案安全提示——危险场景下的用户安抚完整。
4. **降级与容错**：首页离线显示缓存 + 骨架屏、换账号不闪旧数据（`index.vue:14`）、封面图失败占位、演示助手一键填完（演示场景效率工具）。
5. **乐龄适老化成体系**：一页一题、自动朗读、语音作答、登录流程固定标准样式避免"新用户被放大字号吓到"（issue #3）。

## 四、潜在风险与遗留问题（体验视角）

### 4.1 体验风险

| 风险           | 等级 | 说明                                                                              |
| ------------ | -- | ------------------------------------------------------------------------------- |
| 年龄兜底错判       | 🔴 | H1 未修复前，所有跳过资料的用户都在收错误分支的题、按错误年龄出方案，且**平台无法事后发现**（数据里看不出是兜底值还是真实值，建议先给兜底值加标记字段） |
| "提交即失联"的信任损耗 | 🔴 | 意向、预约、转介三个环节都依赖"顾问会联系您"，无跟踪页 + 无主动推送（订阅消息未接）叠加，用户感知是"石沉大海"，对以信任为核心的乐龄客群伤害最大     |
| 语音承诺与真机落差    | 🟡 | 乐龄模式的"说出答案/按住说话"在微信真机小程序上依赖同声传译插件（未接），核心卖点在真机演示时不可用，建议接入前在真机隐藏入口避免"按了没反应"       |
| 美团风格改造未完成    | 🟡 | 文档 issue #1 第一步仅完成门店页，首页/方案页项目卡仍是旧风格，用户在"门店页（黄）→ 方案页（旧）"间跳转时风格断裂                |

### 4.2 遗留体验债清单

测评全局进度（C3）、结果页 CTA（B2）、意向跟踪（B3）、方案执行反馈（D1）、时段预约（A4）、魔镜流式（C4/M5）——均已在上面分级，此处仅确认：**无"文档承诺但代码未做"的隐瞒项**，文档 P2 待做清单与代码现状一致。

### 4.3 体验优化路线图建议

```
第一周（断点修复包）              第二~三周（效率与留存包）         第四周起（随 V1.2）
├─ H1 年龄补采（含兜底标记）       ├─ M3 方案执行打卡联动            ├─ M4 时段预约（依赖医院号源）
├─ H2 体检券代核销路径             ├─ M1 双层进度 + M2 触控区        ├─ M5 魔镜流式输出
├─ H3 我的预约与意向页             ├─ M6 C2 展开式知情               ├─ 真机语音插件接入
├─ H4 结果页 CTA + 真分享          ├─ M7 魔镜上限预告                └─ 美团风格 P2 收尾（首页/方案页）
└─ H5 语音入口扩展                 └─ L1/L2 文字化与可点击项
```

**节奏原则**：

1. **先修断点，再做增强**——H1–H5 全部是小改动大收益（多数是文案、入口、一个新页面），一周内可全部上线；
2. 测评完成页是全漏斗的"动机峰值页"，H4 的 CTA 改造完成后，应同步在埋点（已有 `wf.event` 体系）中增加结果页 → 券页 → 预约页的点击漏斗，用数据验证改造效果；
3. M3（方案执行联动）是留存结构中投入产出比最高的一项：方案、打卡、存折、魔镜待办四套系统已有数据基础，缺的只是前端的勾选交互与积分联动，打通后日活场景从"测评单次"变为"执行每日"。
