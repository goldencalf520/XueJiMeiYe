# 小程序图形资源替换说明 v2.3

> 目标：把项目中「可视觉化的位置」从**单色描边图标**升级为**开源彩色图形 / 徽章 / 合成动图**，
> 全部使用可商用的开源资源，并记录每处替换的用途、适配方式与注意事项。
>
> 配套预览：`docs/09_demo_图形资源与徽章预览.html`（47 个图形实样 + 徽章三态 + 7 类动图 + 三套皮肤实时切换）

## 1. 先说四个决定方案走向的技术事实

这四条都是在项目里实测得出，不是推测。它们直接决定了「什么能做、什么不能做」。

### 1.1 项目现有图标全是「单色」，根因是 mask 模式

UnoCSS 生成图标时会自动判模式，判据是 **SVG 里有没有 `currentColor`**：

```
_mode === 'auto' → parsed.svg.includes('currentColor') ? 'mask' : 'bg'
```

- `i-tabler-*` 走 **mask**：`-webkit-mask: var(--un-icon)` + `background-color: currentColor`
  → 形状保留、**颜色被完全替换为文字色**。这是它能在三套皮肤下自动换色的原因，也是它**永远只有一种颜色**的原因。
- 所以「图标不够丰富」不是审美问题，是**渲染模式**问题。要上彩色，必须走 **bg 模式**（`background-image`）。

**实测确认：** 项目当前 113 条 `i-tabler-*` 规则全部是 mask；新增的 47 条 `i-graphics-*` 全部是 `background: url("data:image/svg+xml;utf8,...")`，且原始色值（如 `#26c9fc`）完整保留。

### 1.2 彩色图形一旦走 bg 模式，就**不能再改色**

这是取舍的核心：mask 可以换色、bg 可以彩色，**不可兼得**。因此分工是：

| 类型 | 组件 | 模式 | 能否换色 | 适用 |
|---|---|---|---|---|
| 功能性图标 | `XIcon` | mask | ✅ 跟随主题 | 箭头、勾选、表单、tabbar |
| 情感化图形 | `XGraphic` | bg | ❌ 颜色固定 | 六维、徽章、玩法、情绪 |

**结论：功能性图标不替换。** 把 tabbar、箭头、勾选换成彩色图形会破坏换肤能力与选中态语义。

### 1.3 小程序不支持 `<svg>` 标签，且 CSS 里的 SVG 不播动画

- 小程序模板里**不能写 `<svg>`**，SVG 只能通过 `background-image` / `-webkit-mask` / `<image src>` 三种方式引入。
- `background-image` 内联的 SVG **不会播放** SMIL / CSS 动画（被当作静态位图）。
- Lottie 需要 `lottie-miniprogram` 运行时（额外体积 + 许可需逐条核对）。

**结论：动图不用外部动图资源，改为「分层元素 + CSS 动画」合成。** 零资源体积、零许可风险、可被现有三级动效档位统一降级。

### 1.4 图形素材必须放 `src/icons/`，不能放 `src/static/`

`src/static/` 下的文件会被 uni-app **全量拷贝**进产物 —— 同一份图形既进 CSS 又进包，**体积翻倍**。
`src/icons/` 只作为构建期素材被 UnoCSS 读取，不进产物。

### 3.3 ✅ 档案页 / 六维周报的维度标识（D17 落地结论由 `XJ-601` 给出）

| 项 | 内容 |
|---|---|
| 位置 | `pages/archive/index.vue`、`components/XRadar.vue`、`pkg-archive/weekly.vue`（规划中） |
| 现状 | 雷达图只有文字标签，没有维度图形 |
| 决议 | 雷达图标签旁加 16px 的 `dim-*` 图形；周报每个维度用 28px 底座图形做行首 |
| 适配方式 | 直接用 `DIM_GRAPHIC`（`xj/graphics.ts` 提供 `code → 图形名` 映射，与 `DIMS.code` 对齐） |
| 落地结论 | 见下方「叠加方案」，消费方为 `XJ-208` / `XJ-703` |
| 注意事项 | 雷达图是手写 SVG（`xj/utils.ts` 的 `radarSvg`），**不要在 SVG 内部放图形**（小程序 SVG 不支持嵌套外部图像）；图形要作为独立的兄弟节点叠在图上 |

**叠加方案（D17 落地结论，`XJ-601` 给出）**

1. **坐标已现成，不要另算角度。** `xj/utils.ts` 的 `radarLabels(scores)` 已按雷达图同一套角度公式返回每个维度的
   `left` / `top`（百分比）：`ang = -π/2 + i·2π/6`，`left = 50 + 50·cos(ang)`，`top = 50 + 50·sin(ang)`。
   图形直接复用这套坐标；自行重算角度必然与网格错位。
2. **结构**：容器 `position: relative`，雷达图本身作为 `background-image`；图形与文字标签同为绝对定位的
   `<view>` 子节点，`left` / `top` 取 `radarLabels()` 的值，再用 `translate(-50%,-50%)` 做中心补偿。
3. **尺寸与降级**：图形 16px（乐龄 20px），尺寸走 `--gd-*` 继承变量（组件内不写皮肤选择器）；
   `DIM_GRAPHIC[code]` 未命中时**回退 `XIcon`**（`DIMS[].icon` 字段仍保留），不留空白。
4. **⛔ 禁止**：把图形写进 `radarSvg()` 拼出的 SVG 字符串内部 —— 小程序 SVG 不支持嵌套外部 `<image>`，
   且内联 SVG 不播动画。
5. **边界**：`XJ-601` 只交付图形资源与坐标约定，实际消费在 `XJ-208`（测评雷达生长）与 `XJ-703`（档案模块动态化）。

## 4. 组件与用法

### 4.1 `XGraphic` —— 彩色图形

```vue
<!-- 裸图形：25px，无底座 -->
<XGraphic name="badge-fire" :size="25" />

<!-- 带底座：尺寸与配色随皮肤/乐龄自动变化 -->
<XGraphic chip chip-size="md" tone="care" name="dim-skin" />
```

`chip-size`：`sm`(28) / `md`(38) / `lg`(46)，乐龄自动放大为 34 / 46 / 56。
`tone`：`plain` / `gold` / `care` / `terra` / `rose` / `sky` / `plum`，与 `.icon-box` / `.ic-chip` 色名一致。

### 4.2 `XBadge` —— 成就徽章

```vue
<XBadge
  icon="badge-trophy"      <!-- 已解锁的彩色图形 -->
  outline="trophy"          <!-- 未解锁的 Tabler 线稿 -->
  label="积分达人"
  state="unlocked"          <!-- locked | unlocked | new -->
  size="md"
  :progress="0.42"          <!-- 仅 locked 时显示进度条 -->
/>
```

### 4.3 合成动图类（挂在任意元素上）

| 类 | 形态 | 典型用途 |
|---|---|---|
| `.gd-bob` | 轻微浮动 | 待办未完成、新入口引导 |
| `.gd-spin` | 匀速旋转 | 加载环、进行中 |
| `.gd-pulse` | 呼吸缩放 | 在线状态、可领取 |
| `.gd-pop` | 弹入（一次性） | 新解锁徽章 |
| `.gd-shine` | 扫光 | 可领取、新权益 |
| `.gd-halo` | 光晕扩散（一次性） | 庆祝时刻 |
| `.gd-float-up` | 上浮消退（一次性） | `+5 积分` 浮字 |

### 4.4 图形注册表

`src/xj/graphics.ts` 是唯一的图形清单，提供 `GRAPHICS`、`DIM_GRAPHIC`、`graphicClass()`。

> ⚠️ **维护约束**：`GRAPHICS` 的值必须写成**完整类名字面量**（`'i-graphics-dim-skin'`），
> 不能拼接（`` `i-graphics-${name}` ``）—— UnoCSS 是静态扫描，拼接的类名不会被生成，图标会静默消失。
> `uno.config.ts` 的 `safelist` 里做了冗余登记，双保险。

### 4.5 更新图形资源

```bash
node ./scripts/fetch-graphics.js          # 增量补齐
node ./scripts/fetch-graphics.js --force  # 强制重下（换源或升级时）
```

## 5. 皮肤与降级适配

所有皮肤差异都表达为**继承的自定义属性**，不在组件里写任何 `.elder` / `.night` 选择器。

| 皮肤 | 底座 | 徽章 | 动图 |
|---|---|---|---|
| 柔金轻奢（默认） | 白底 / 浅金渐变 | 暖金渐变盘 + 金环 | 全效 |
| 乐龄墨绿 | 尺寸放大到 34/46/56，底色转暖白偏绿，tone 全部归一到浅绿（减少色彩噪声） | 盘径 56/68/80，绿环 | **全部静止** |
| 臻享夜色金 | 半透明金底 + 描边提亮（保证深底对比） | 半透明金盘 + 金环 | 全效 |

三级动效档位（`docs/08`）对循环类动图的处理：

| 档位 | 循环动图（bob/spin/pulse/shine） | 一次性动图（pop/halo/float-up） |
|---|---|---|
| 满效 `mo-full` | 正常 | 正常 |
| 轻效 `mo-lite` | **静止** | 保留（瞬时结束，成本极低） |
| 关闭 `mo-off` | **静止** | **静止** |

> 轻效档位的设计判断：它是「低端机 / 省流」，继续跑无限循环动画是主要掉帧来源；
> 而装饰性循环动画不承载信息，静止不影响可用性。

**⚠️ 已知注意点：** UnoCSS 的 bg 模式会写入 `background-size: 100% 100%`。
本批 47 个图形的 `viewBox` 都是正方形（24×24），不会失真；
**将来换成非正方形图形时必须显式覆盖 `background-size: contain`**，否则会被拉伸。

## 6. 体积预算（实测）

| 项 | 数值 |
|---|---|
| 图形源文件（47 个 SVG） | 45.9 KB |
| 构建后内联进 `app.wxss` | **55.9 KB**（47 条规则，`XJ-601` 当次实测） |
| `app.wxss` 总量 | 117.7 KB（无图形规则基线）→ **173.6 KB**（含全部 47 条） |
| 其中单色图标（113 条 Tabler） | 约 76 KB |
| **主包体积** | **427 KB / 2048 KB**（余量 1621 KB，早期批次口径） |
| 分包合计 | 289 KB / 20480 KB（早期批次口径） |

**结论：体积无压力，余量充足。**

**`XJ-601` 的增量口径（重要）**：本卡**不新增任何图形资源** ——
§3.3 维度标识复用 `dim-*`（6 枚已在清单内）、§3.5 封面占位复用 `store-bag` / `care-warn`、
§3.6 加载环为纯 CSS 合成、§3.7 明确空状态不替换。
因此本卡对包体积的**净增量为 0 KB**，满足 AC「≤ 20 KB」。
上表 55.9 KB 是 47 个图形**作为整体**进入 `app.wxss` 的总成本，属 P0-a 资源层的既有支出，不是本卡新增。

一个需要知道的取舍：`safelist` 会**无条件生成**全部 47 条图形规则，即使当前只有 13 个被页面实际使用。
这是有意为之（避免"写了类名却没生成图标"这类静默故障），成本 55.9 KB；
如果将来需要极限压缩，可以只把**已启用**的图形写进 `xj/graphics.ts`，其余移出清单。

其他可回收项：`static/images/avatar.jpg` 57.4 KB（零引用）。
